# ADR-0002: CQRS — separar modelo de escrita e de leitura

- **Status:** Aceito
- **Data:** 2026-08-28

## Contexto
O modelo de escrita (agregado Event-Sourced) é ótimo pra garantir invariantes,
mas péssimo pra consulta: montar um extrato reproduzindo eventos a cada request
não escala. As necessidades de escrita e leitura são assimétricas.

## Decisão
Adotar **CQRS**. O lado de escrita usa commands que passam pelo agregado e geram
eventos. O lado de leitura usa queries que batem em um **read model** dedicado,
alimentado por projeções que consomem os eventos.

## Consequências
- (+) Leitura rápida e desenhada pra UI (saldo, extrato paginado).
- (+) Escrita e leitura evoluem e escalam independentemente.
- (−) Consistência eventual entre escrita e read model (aceitável para extrato).
- (−) Mais peças: projeções e sincronização.

## Alternativas consideradas
- **Ler direto do event store:** simples, mas lento e acoplado ao formato de evento.
